## Abstract

Ratifies the core AIFP-1 payment protocol – the HTTP 402 challenge/quote/pay/receipt loop, Ed25519‑signed stateless receipts (TTL 600 s), pricing tiers, 1 % protocol fee, merchant settlement of 99 %, idempotency (24 h window), and the error registry. The full normative description lives in **Doc 01** (`docs/aifp/01-AIFP-1-RFC-Payment-Protocol-Specification.md`).

## Motivation

Provide a minimal, interoperable, machine‑readable payment handshake for AI agents and other autonomous software, enabling micro‑transactions at sub‑cent‑scale while preserving strong security and enterprise‑grade performance.

## Specification

### Payment Flow

1. Agent requests a protected resource.
2. Merchant returns **402 Payment Required** with a JSON **Payment Challenge**.
3. Agent obtains a **quote** via `POST /v1/quote`.
4. Agent pays the quoted amount via `POST /v1/pay`.
5. AiFinPay issues an Ed25519‑signed **Receipt Token** (JWT).
6. Agent retries the original request with `Payment‑Receipt: <JWT>`.
7. Merchant verifies the receipt locally (signature, expiry, nonce) and grants access.

### Pricing Tiers

| Tier | Minimum Price |
|---|---|
| `standard` | $0.00001 |
| `complex`   | $0.00006 |
| `premium`   | $0.00010 |

### Fee Structure

- **Protocol fee:** 1 % (0.01) applied to each transaction.
- **Merchant settlement:** 99 % (0.99) after deducting the protocol fee and any network costs.

### Receipt Properties

- **Format:** JWS‑signed JWT (EdDSA/Ed25519).
- **Claims:** `iss, sub, aud, resource, amount, nonce, iat, exp, kid`.
- **TTL:** 600 seconds (default).

### Idempotency

- **Deduplication window:** 24 hours.
- **Header:** `Idempotency-Key` – unique per request.

### Supported Networks

12 chains with stable‑coin support (USDC/USDT/PYUSD) – see Appendix B of Doc 01.

## Backward Compatibility

This AIP defines the baseline protocol. All future extensions must be **backward‑compatible** (MINOR) unless a **MAJOR** version bump is performed with a parallel deprecation window of ≥12 months.

## Security Considerations

- **Receipt forgery prevention:** Ed25519 signatures verified against the AiFinPay JWKS.
- **Replay protection:** Single‑use nonce embedded in both challenge and receipt; nonce store must be linearizable.
- **Stateless verification:** No backend calls required for receipt validation, enabling high‑throughput verification (~50 k/s per core).

## Reference Implementation

Reference implementations reside in the `sdk/` and `sandbox/` directories. Conformance tests in `tests/` exercise the full flow against the specification.

## Test Cases

The conformance suite includes:

- Challenge generation and format validation.
- Quote negotiation, error handling.
- Payment processing, receipt issuance, and signature verification.
- Idempotency enforcement across duplicate requests.
- Replay‑attack (reused nonces) attempts.
