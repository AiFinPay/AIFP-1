## Abstract

Records the protocol-level addition of Unichain as a network identifier/candidate settlement environment.

## Status Clarification

`Final` here means this AIP's protocol/governance decision was accepted. It does **not** prove that Unichain, or any historical network count associated with this proposal, is currently AIFP-1 payment-live under the latest `100/0` economic profile.

Current payment-live status must be established from the canonical deployment registry, source provenance, verifier support, SDK/backend support, and end-to-end evidence.

## Motivation

Allow AIFP implementations to represent Unichain as a supported network capability without breaking clients that do not use it.

## Specification

An implementation that exposes Unichain for payment must identify:

- chain/network identifier;
- canonical settlement target;
- supported assets and decimals;
- active AIFP route/economic profile;
- verifier implementation;
- SDK transaction semantics;
- deployment/conformance evidence.

A network identifier may exist in the protocol even when a live payment route is disabled.

## Backward Compatibility

Additive network identification is backward-compatible for clients that ignore unsupported networks. Activating a new payment route is a separate deployment/release decision.

## Security Considerations

Do not assume security review or payment readiness merely from this AIP's status. Before enabling value transfer, complete chain-specific source/deployment verification, economic-profile checks, token-decimal checks, settlement-verifier tests, replay/idempotency tests, and the appropriate independent release review.
