## Abstract

Defines payment channels for high-frequency metered consumption with escrow bound to the Agent Passport.

## Motivation

Enable streaming micropayments for continuous resource consumption without per-request overhead.

## Specification

### mSECCO Channels

- Bi-directional payment channels for agent-to-merchant streaming
- Escrow bound to Agent Passport (`pp_*`)
- On-chain settlement on channel close

### Channel Lifecycle

1. **Open**: Agent locks funds in escrow
2. **Stream**: Metered deductions per consumption unit
3. **Close**: Final settlement on-chain

### Protocol Negotiation

Gated by Protocol Negotiation Layer (AIFP-1 §22.3) — opt-in capability.

## Status note (2026-08-07)

Withdrawn. This AIP builds channels on **mSECCO**, which the team retired on
the 2026-08-06 advisor call: crediting it required an extra chain call on every
payment. `MSECCOToken` on Polygon has `totalSupply: 0` — it was never minted —
and `B2BSplitter`, which carries every production payment, has no reference to
it at all.

The underlying goal is live: pooling prepayment so a small consumer does not
pay a per-merchant floor. It should be re-proposed against escrow the agent
controls plus signed vouchers, and the escrow question — sub-allocation,
over-collateral, or a guarantor — settled in that AIP rather than assumed.
